# Accessibility Baseline

KnowledgeOS targets WCAG 2.1 AA. This document records the patterns we use and known gaps.

## Landmarks

- `<aside>` — sidebar navigation
- `<nav>` — sidebar nav items
- `<main id="main-content">` — primary content area in AppShell
- Skip-link: `<a href="#main-content">Skip to content</a>` in `(app)/layout.tsx` (visible on focus)

## Keyboard Navigation

- All interactive elements are reachable via `Tab`.
- Focus rings use `ring-ring` token (indigo) with 2px width.
- List pages support `j/k` / `↑/↓` for highlight navigation (see `useListKeyNav`).
- The shortcut overlay (`?` key) lists all available keyboard shortcuts.
- Focus is suppressed from `useListKeyNav` when the active element is an input, textarea, or contenteditable.

## Focus Management

- Dialogs trap focus (via Radix UI Dialog) and restore focus on close.
- Search Command palette traps focus while open.
- Modal open/close uses `aria-modal="true"` (provided by Radix).

## Live Regions

- `SaveStatusChip` uses `role="status"` + `aria-live="polite"` so screen readers announce save state changes.
- Auth forms use `aria-live="polite"` + `aria-atomic="true"` on error regions.
- `AssetUploader` toasts fire on upload complete/error (screen readers announce via Sonner's live region).

## Icon Buttons

All icon-only buttons must have either `aria-label` or visible text. The `IconButton` component requires `aria-label` as a mandatory prop.

## Color Contrast

- Dark theme (`data-theme="dark"`): primary text `--text-primary` (#F4F4F5) on `--surface-0` (#09090B) ≥ 7:1.
- Light theme: `--text-primary` (#18181B) on `--surface-1` (#FFFFFF) ≥ 18:1.
- Muted text (`--text-secondary`) achieves ≥ 4.5:1 in both themes.
- Danger/warning/success tokens are paired with white foreground text in status chips.

## Known Gaps

- Editor toolbar (non-V2) has no keyboard shortcut hints in tooltips — tracked for a future polish pass.
- Mobile nav does not trap focus (not yet a full drawer) — acceptable for now given desktop-primary usage.

## Testing

Run axe-core in dev:
```bash
# Install axe for development
pnpm --filter @kos/web add -D @axe-core/react
```

Add to `(app)/layout.tsx` in development mode only. Remove before shipping.

## Phase 13 Audit (2026-05-17)

76 E2E tests run across 22 spec files. No new accessibility regressions found. Existing known gaps remain:

- Editor toolbar (non-V2): no keyboard shortcut hints in tooltips
- Mobile nav: no focus trap (desktop-primary app, acceptable)
- All icon-only buttons verified to have `aria-label` attributes (Add MCP connection, Collapse sidebar, search trigger, etc.)
- `data-testid` attributes added to `AssetUploader` drop zone — no impact on accessibility tree
